# Wave 95 · Prepared Release SHA Stability

## Purpose

Wave 95 closes the identity gap between a development source tree and physical release UAT without granting release authority.

The source contract has exactly two valid states:

- `LOCKED_SOURCE`: development source; `RELEASE_READY=False`; no canonical release tag.
- `PREPARED_RELEASE`: stable version; `RELEASE_READY=True`; `RELEASE_TAG=v<version>`.

Any mixed state fails closed.

## Why this exists

Physical UAT must be executed after the exact release version/tag intent is frozen. Otherwise a team could physically test one commit and later change version/tag source metadata before creating the distribution tag, producing a different source identity despite apparently reusing the same UAT evidence.

Wave 95 therefore binds physical UAT to the same:

- full Git SHA;
- source SHA-256;
- physical candidate manifest SHA-256;
- source-contract generation (`95`);
- stable product version;
- canonical prepared release tag.

## Authority boundary

`PREPARED_RELEASE` is not a release authorization. It does not prove or grant:

- physical UAT PASS;
- Developer ID signing;
- Apple notarization;
- Gatekeeper acceptance;
- GitHub OIDC/Sigstore provenance;
- operational authorization;
- release authority;
- publication authority;
- production readiness.

A prepared source without all external operational evidence remains `SOURCE_CONTRACT_READY` and `production_ready=false`.

## Physical candidate boundary

An exact physical-UAT candidate remains:

- arm64 only;
- ad-hoc signed;
- non-notarized;
- non-production;
- eligible only when generated by a controlled GitHub `push` to `refs/heads/main`;
- never generated from a release tag.

Tag builds remain source-equivalent distribution rebuilds, not exact physical-UAT candidates.

## Evidence chain

Wave 95 carries the source contract through:

1. source readiness;
2. physical candidate manifest;
3. operator handoff;
4. Wave69 physical preflight;
5. release UAT collection and manual recording;
6. combined physical UAT attestation;
7. distribution rebuild identity;
8. production release candidate gate;
9. tag preflight.

Production accepts only a combined physical UAT attestation from the exact W95 `PREPARED_RELEASE` identity and exact prepared tag.

## Preserved release architecture

Wave 95 is upstream hardening. It does not replace downstream trust layers:

1. **W95** · prepared source identity + physical-UAT binding;
2. production gate;
3. immutable native package;
4. **W92** · exact packaged ZIP Apple round-trip trust;
5. **W91** · cross-architecture evidence authorization;
6. **W92** · artifact publication authorization;
7. **W94** · GitHub OIDC/Sigstore provenance and transaction handoff;
8. **W93** · fail-closed transactional GitHub Release publication.

W94 remains non-publication authority. W93 remains the only final GitHub provider mutation/publication transaction.

## Current repository truth

- `0.9.0.dev1`;
- `RELEASE_READY=False`;
- `RELEASE_TAG=None`;

- no external release evidence inferred from source.

## Certification rule

Only the exact final Wave 95 HEAD is eligible for merge after:

- Canonical Source CI Ubuntu PASS;
- Canonical Source CI macOS PASS;
- FULL MAC arm64 PASS;
- persistent Intel x86_64 current-runtime PASS;
- tag-only release jobs SKIPPED on PR;
- branch `behind_by=0` against `main`.

No PR certification may be represented as physical-UAT, Apple notarization, OIDC tag-runtime, or public-release PASS.
